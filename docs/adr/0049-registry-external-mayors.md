# External mayors come from the ACP Registry

Status: accepted

The official [ACP Registry](https://agentclientprotocol.com/get-started/registry) supplies the external mayor catalog and Windows launch metadata. `AcpRegistry` owns the cached index, versioned binary downloads, published checksum verification, and `npx`/`uvx` preparation behind one launch interface; the existing ACP session owns the conversation and city MCP connection. The built-in mayor remains the default. Refreshing the catalog preserves the selected registry id; a missing id or unknown cached format is rejected rather than mapped to another agent. Binary downloads and working files stay outside the watched mod directory. Package agents require the corresponding package runner, and players sign in outside the game.

Only the prompt instructs an external mayor to use city tools. The mod does not inject agent-specific permission settings or reject ACP permission requests by tool name. For a live, owned session it selects `allow_once`, or `allow_always` if that is the only allow option. Unknown sessions and cancelled requests remain cancelled. The client continues to advertise no file or terminal operations because it does not implement them; an agent retains its own capabilities and player configuration. This replaces the catalog, installation and permission choices in [0036](./0036-external-mayor-acp.md), while retaining its ACP and stdio MCP transport.

We considered keeping a manually curated launch table, and moving registry preparation into another executable. A registry-backed module removes per-agent launch maintenance while avoiding an extra process between the game and the agent. No agent-specific timeout override is retained: the registry's OpenCode 2.2.5 [MCP client](https://github.com/anomalyco/opencode/blob/v2.2.5/packages/core/src/mcp/client.ts) defaults ordinary tool execution to 12 hours, so the old 45-minute override is unnecessary. Long city advances remain a live acceptance gate.
