# Analyze recordings inside the existing worker

The offline viewer's recording worker owns model usage, context and cache analysis, tool summaries, and paged full-text search over records and referenced JSON/text assets. A recording analysis module hides traversal and aggregation behind `analyze` and `search`; the page receives bounded rows rather than resolving large attachments again. Per-tab traversal was rejected because it duplicates evidence rules and moves long-session work onto the UI thread. The checker and viewer share one write-evidence judgment.

Recordings include first-content and first-answer latency attributes plus model duration and standard usage metric definitions. Empty and usage-only updates are excluded at capture; reasoning is content, while the first answer may be text or a tool call. Non-streamed content becomes observable at response completion. Analysis reads the captured model duration and latency attributes directly and leaves missing values unavailable; it does not recompute duration from span timestamps or reinterpret historical output contents to reconstruct those metrics. Successful calls supply latency percentiles; all reported usage contributes to token totals, with coverage counts and unavailable values preserved. Cache reuse divides cache-read tokens by input tokens only for calls reporting both; cache and reasoning tokens remain subsets, never additional input/output totals.

Analysis and search cover the whole recording independently of the playback cursor. Run and turn filters include background origins, and search navigates to the exact matching record before exposing its evidence. JSON references are searched once per query; text attachments are read on demand, and binary files are excluded. Searches yield between batches and superseded requests stop so playback and later queries remain reachable. This extends [0052](0052-trace-kit-session-records.md) without another on-disk contract or an external collector.
