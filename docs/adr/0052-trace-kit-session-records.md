# Trace-kit is the session record format

Status: accepted

Use trace-kit records as the only persisted event contract. The C# session record writes `records.jsonl` and content-addressed `assets/` inside the game's process. Source lifecycle records delimit the recording, and `session.fact` records carry its facts; absent source completion means an interrupted recording. The old session manifest and timeline envelope are removed without migration. The actual TypeScript trace-kit schema, reader and projections power both the offline checker and graphical viewer. Until trace-kit is published independently, installation pins an upstream source revision.

Harness and MEAI native activities supply agent, model and function evidence, including native events and causal links. An in-process adapter converts them once. A narrow model-client observer checkpoints native request attributes and input message identities before transmission, then persists every returned update before yielding it. Native final capture preserves assembled output and usage; delta records preserve the output's actual evolution, including returned reasoning and typed content. Player input arrival, queuing and application, Stop, plan changes, actual compaction and history repairs explain how those calls were reached. Cancellation and failure remain distinct from successful completion. Native agent sessions and runs have immutable scoped identities; background work retains its originating relation after the root ends. City-tool outcomes, simulation anchors, before/after write evidence and returned files enrich the same trace. External ACP notifications, output deltas, permissions and child lifecycle are recorded at the observable protocol boundary; external model internals remain explicitly unobservable.

Preserve native activity identity in either W3C or hierarchical format. Unity's runtime can use hierarchical agent activities alongside W3C model and tool activities; the adapter resolves their parent identities without changing the game's global activity format.

Use the run's cancellation request to distinguish cancellation from failure, including Unity HTTP transport aborts that throw `WebException`. Keep the original exception, `error.type` and `otel.status_code`, and record whether cancellation was requested. A normally completed activity stays completed even if Stop arrived concurrently. Chat outcomes and history-repair reasons use that same request; an unrequested transport abort or provider `OperationCanceledException` remains a failure.

Build the viewer as one self-contained HTML file that opens a selected session directory locally. It uses trace-kit's projections for the execution timeline and branches, exposes referenced evidence, and replays recorded output with pause, step and seek. Playback projects only the prefix reached by the cursor, so final output cannot appear early. Relative elapsed time and source sequence are enough for this task; a mandatory live service and high-frequency clock synchronization would add operational cost without helping explain city decisions. Abrupt termination leaves an incomplete trace whose flushed updates can still be inspected and replayed. Bytes not received by the observer and writes interrupted by process or storage failure cannot be promised.

All records, including streaming updates, enter trace-kit's reader indexes. Its timeline projection receives structural events rather than every output chunk; chunk order and content remain in the event list and output replay. This avoids the upstream projection's repeated same-track instant scans on long sessions. When the browser supports directory handles, opening a folder resolves only referenced files rather than enumerating the folder first. Import reports its stages and validates attachments in bounded batches.

The checker and browser share one recording loader, asset store and lifecycle validator. Their filesystem adapters supply bytes; the command-line adapter also checks resolved paths stay inside the selected recording. JSON assets are parsed and cached once during import. The writer redacts JSON trees before a single serialization, then shares hashing and file storage with text and binary assets; it does not serialize a tree only to parse it again.

History snapshots and native model input/output lists keep ordered asset references to individual message bodies. Content hashes identify immutable versions: an unchanged message reuses its body, while an edit writes a new body and leaves earlier evidence intact. Snapshot counts, token estimates and message identities remain on the snapshot. Each list stands alone; replay does not require a chain of history patches. Native and client message representations remain in their original shapes rather than introducing a conversion between SDK contracts.

Model and ACP output deltas persist their complete redacted payload as an inline JSON string in `airimayor.data`, which trace-kit's primitive attribute contract accepts. Each event is appended and flushed before the update reaches its caller. Streaming text does not create asset files; returned binary files remain separate. The shared loader parses inline payloads once, validates their nested references and reuses them for replay, search and attachments. File-backed output deltas are rejected. This targets repeated history bodies and one-file-per-fragment overhead without adding a database, compression blocks, a custom index or a patch protocol.

The offline viewer uses AIRI's `ui-trace`, `ui-timeline`, `timeline-canvas` and shared UI from the same pinned source revision as trace-kit, compiled as a Vue application with the upstream trace translations and generated UnoCSS styles. `TraceTimeline` owns entity lanes, track rows, nesting, pan, zoom, hover cards and causal handoffs; `TraceDetail` owns parent/child and incoming/outgoing link navigation. `TraceEventLog` supplies its existing virtual list, and `TraceMetrics` reads the standard metric projections. The host resolves local assets and displays city evidence and recorded output. Vue's dependencies do not prevent a self-contained offline file. Reusing these modules removes the duplicate presentation model, handwritten SVG and the replacement React/vis-timeline interface.

A Web Worker owns file validation, the complete reader, replay and evidence resolution; Comlink supplies its interface. The page builds AIRI view readers once from structural records for the overview, and on demand from the reached prefix for details. Selecting a reached call preserves the cursor so its available arguments and result stay visible; Replay from selection explicitly starts at its first record. Stable view versions and selection identities keep playback cursor updates from rebuilding the overview. The complete event log loads only when opened, using the actual event-log projection with an unlimited offline limit rather than its bounded live default. All output chunks remain there and in the indexed output replay. Playback batches due updates into one in-flight frame and discards stale results immediately on Pause. Repeated seeks coalesce to the latest requested position. Evidence and visible raw records load on demand while playback is paused; large collections use a virtual JSON tree, and full values remain downloadable. This keeps expensive prefix reconstruction off the UI thread without introducing a server or another persisted contract.

This supersedes the disk layout and capture omissions in [0046](0046-session-record.md) and [0048](0048-native-maf-harness.md). The write-evidence judgment in [0047](0047-write-evidence.md) remains. Rebuilding model serialization would duplicate SDK knowledge; a mandatory TypeScript host would add transport recovery and another process without exposing additional evidence.
