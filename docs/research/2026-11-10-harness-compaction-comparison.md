## OpenCode: append the task to the ordinary request

The current implementation prepares the ordinary system instructions, conversation and tool definitions, then appends a **user** summarization request after hooks. That request forbids continuing the task or calling tools and provides a structured handoff template. When the request fits and the model remains the same, this preserves the prior request prefix rather than replacing its system instruction. A configured compaction model can differ from the conversation model. [Prompt and model selection](https://github.com/anomalyco/opencode/blob/54de420baa78986dbc53c76c4524a191b3f08601/packages/core/src/session/compaction.ts#L214-L298), [send path](https://github.com/anomalyco/opencode/blob/54de420baa78986dbc53c76c4524a191b3f08601/packages/core/src/session/compaction.ts#L471-L545).

Tool definitions remain, but the compaction consumer does not execute tool calls. It does not explicitly set `toolChoice: none`. A weak structural check accepts any one expected template heading; otherwise one additional user nudge is appended and a second unsuitable response fails. This is not factual validation of the summary. [Request preparation](https://github.com/anomalyco/opencode/blob/54de420baa78986dbc53c76c4524a191b3f08601/packages/core/src/session/compaction.ts#L790-L870), [checks and nudge](https://github.com/anomalyco/opencode/blob/54de420baa78986dbc53c76c4524a191b3f08601/packages/core/src/session/compaction.ts#L486-L521).

Overflow recovery can use a shorter unchanged prefix, then flatten history into text, dropping tool definitions, reasoning and media. After successful compaction, subsequent requests contain a historical user checkpoint with summary and recent-context sections, followed by new turns. That replacement changes the history prefix. Optional precomputation defaults to false and can hold a summary until needed. These paths differ from historical OpenCode V1 reports. [Delivery and fallback](https://github.com/anomalyco/opencode/blob/54de420baa78986dbc53c76c4524a191b3f08601/packages/core/src/session/compaction.ts#L643-L787), [checkpoint](https://github.com/anomalyco/opencode/blob/54de420baa78986dbc53c76c4524a191b3f08601/packages/core/src/session/runner/to-llm-message.ts#L273-L290), [precomputation](https://github.com/anomalyco/opencode/blob/54de420baa78986dbc53c76c4524a191b3f08601/packages/core/src/session/compaction.ts#L266-L363).

## Pi: make the old conversation source material

Pi uses a dedicated summarizer system prompt followed by one user message. Old messages are serialized into text inside `<conversation>`, optionally followed by the previous summary, and the actual summarization instructions come **after** that material. The source explicitly explains that serialization prevents treating the history as a conversation to continue. It omits thinking and truncates tool results. [Framing and serialization](https://github.com/earendil-works/pi/blob/b2aabe02966a6b4528c7498a3bb406c14396932d/packages/coding-agent/src/core/compaction/utils.ts#L107-L164), [request construction](https://github.com/earendil-works/pi/blob/b2aabe02966a6b4528c7498a3bb406c14396932d/packages/coding-agent/src/core/compaction/compaction.ts#L681-L740).

This dedicated request has no tool definitions. The response is rejected if it contains a tool call. Summary calls set `cacheRetention: "none"` to avoid cache writes for one-off summaries; an existing session routing ID can still be reused. This option should not be interpreted as a provider-independent guarantee of zero cache reads. Reformatting the transcript prevents preserving the original conversation token prefix. [Request options](https://github.com/earendil-works/pi/blob/b2aabe02966a6b4528c7498a3bb406c14396932d/packages/coding-agent/src/core/compaction/compaction.ts#L619-L637), [tool-call rejection](https://github.com/earendil-works/pi/blob/b2aabe02966a6b4528c7498a3bb406c14396932d/packages/coding-agent/src/core/compaction/compaction.ts#L742-L752).

Pi persists the summary and retained-message boundary, then rebuilds normal context from system instructions, summary and retained recent messages. [Official compaction reference](https://github.com/earendil-works/pi/blob/b2aabe02966a6b4528c7498a3bb406c14396932d/packages/coding-agent/docs/compaction.md).

## Codex guidance / Responses: provider-native compaction

The Codex prompting guide describes `/responses/compact`: send the current window and carry the returned compacted window into subsequent requests. It contains an opaque encrypted compaction item rather than a client-authored textual summary. The current API also supports server-triggered compaction through `context_management`. These docs do not disclose internal summary instruction ordering, nor establish which path every Codex client uses. [Codex guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide#compaction), [API compaction guide](https://developers.openai.com/api/docs/guides/compaction).

OpenAI explicitly documents that replacing earlier context can reduce cache reuse on the first post-compaction request. Stable instructions can remain reusable; subsequent turns build on the new compacted prefix. Native compaction does not imply that the old full-history KV prefix survives. [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching#compaction-can-reduce-cache-reuse).

## Implications for the local failure

The [local investigation](./2026-11-10-native-summary-upstream-reports.md) concerns MAF's dedicated summary system instruction followed by original conversation messages, without a fresh trailing summary request. OpenCode and Pi demonstrate two distinct alternatives: preserve the ordinary conversation prefix and append a task, or explicitly turn history into quoted source material and append a task within that wrapper. Pi also demonstrates why a leading system instruction alone is not evidence of a defect.

Inference: OpenCode is the closer comparison when preserving cache eligibility during the summary call matters; Pi provides clearer separation between historical actions and the current summarization task. Neither source inspection proves quality or actual cache-hit rates for our OpenCode Go / DeepSeek route. Generating a summary with a reusable prefix and replacing old history afterward are separate cache events. No product strategy is selected or implemented by this note.
